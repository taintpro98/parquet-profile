Bài toán

Một truy vấn duy nhất, một file mỗi ngày, pod 4 CPU / 4 GiB

  • Truy vấn: REFERENCE + CREATED_AT → một bản ghi đầy đủ 73 cột. Không lọc, không đếm, không thống kê.
  • Quy mô: ~10 triệu dòng/ngày, mỗi ngày một file archive.
  • Ghi một lần bởi một tiến trình, sau đó chỉ đọc.
  • Chỉ định dạng và thư viện chuẩn, không tự chế định dạng hay index riêng.

Hai biến thể RocksDB, một Parquet

Đề xuất

java-rocksdb

RocksDB (SST), index + bloom phân vùng, ZSTD.

Java 25, rocksdbjni, ojdbc lô 10.000.

Đối trọng

go-rocksdb

Cùng định dạng, file giống hệt bản Java.

Go, grocksdb, godror lô 1.000, tắt prefetch. Cần Oracle Instant Client và cgo.

Để so

java-parquet-duckdb

Parquet, row group 128 MB, dictionary, ZSTD.

Java 25, parquet-java ghi, DuckDB đọc, ojdbc lô 10.000.

Mọi phương án đọc cả ngày bằng một câu SELECT như khi chạy thật. Ngày 1M / 2M dòng dựng từ bảng 100k dòng bằng UNION ALL 10 / 20 lượt.

Đề xuất

Định dạng RocksDB SST, triển khai bằng Java

≈60×nhanh hơn Parquet khi tra 1000 key (0,91 s so với 53,4 s ở 1M), khoảng cách tăng theo kích thước file
−45%RAM đỉnh khi dump so với Parquet (644 MB so với 1,16 GB)
  • Tra cứu là truy vấn duy nhất. RocksDB có index + bloom theo key, chỉ đọc đúng block chứa key. Parquet theo cột: 1000 key ngẫu nhiên chạm gần mọi row group, phải giải nén gần hết file.
  • Đổi lại: file lớn hơn Parquet ~11% (74 so với 66 GB/ngày).
  • Java hay Go: file giống hệt nhau. Go dùng ít RAM hơn (182 MB) và nhanh hơn, nhưng cần Oracle Instant Client + cgo khi build và vận hành. Java là mặc định; Go là phương án dự phòng nếu RAM trở thành ràng buộc.

Thiết kế ColdBoy · toàn vẹn

Không bao giờ để lại archive dở, không trả dữ liệu sai

  • Đọc cả ngày bằng một câu SELECT … ORDER BY REFERENCE, ghi SST ra ổ cục bộ, fsync.
  • Băm SHA-256 từng file, lưu cạnh archive và trong catalog.
  • Copy lên NAS dưới tên tạm, đổi tên khi xong.
  • Verify băm lại trên NAS; khớp thì ngày chuyển archived.
  • Single writer: một job dump, một tiến trình ghi một archive.
  • Lỗi giữa chừng: ngày ở failed, không có file nào trên NAS dưới tên thật.
  • Mỗi lần đọc, RocksDB kiểm checksum của block đã đọc; hỏng thì báo lỗi.
  • Archive trên NAS không bị ghi thêm; log và lock để ở ổ cục bộ.
  • ColdBoy không xoá dữ liệu Oracle; chủ nguồn xoá sau khi ngày đã archived và verify.

Dung lượng11
Việc tiếp theo

Những gì cần xác nhận trước khi triển khai

  • Đo trên mẫu dữ liệu thật (avg_row_len, mức lặp) để chốt dung lượng NAS.
  • Đo 3M / 10M dòng trực tiếp khi có đủ ổ đĩa (~80 GB cho 10M).
  • Oracle ở xa qua mạng sẽ làm dump chậm hơn số đo cục bộ; cần đo trong mạng thật.
  • Thiết kế catalog: bảng job dump, trạng thái ngày, file + SHA-256.
  • Bảo mật: TLS, xác thực client, phân quyền admin, log truy vấn.
  • Chốt ngôn ngữ: Java mặc định; xem lại Go nếu RAM pod bị siết.
